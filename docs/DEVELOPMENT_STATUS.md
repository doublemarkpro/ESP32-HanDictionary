## 容量结论

现阶段可以继续推进学习工具，但必须保持“代码和小型 UI 资源在 Flash，大型字库/音频/笔顺在 SD”的分工。Tab5 官方配置为 [16 MB Flash、32 MB PSRAM](https://docs.m5stack.com/en/core/Tab5)。PSRAM 是运行内存，不是可断电保存的容量。

第二轮 P4X 实测编译结果：应用 4,370,752 字节，5 MiB 分区剩 872,128 字节（16.6%，约 852 KiB）；相比上一轮应用减少 292,864 字节。保留 4 bpp 的字体无损压缩，同时增加了 44 音卡片、矩字、SD 笔顺和诊断工具。压缩效果经过实际 LVGL 栅格解码及截图检查。

Legacy 版本也已编译通过：应用 4,347,072 字节，剩 895,808 字节（17.1%，约 875 KiB）。独立烧录包位于本机 `dist/firmware/ui2-P4X` 与 `dist/firmware/ui2-Legacy`，未改变上一轮分区布局。

资源分区容量 6,160,384 字节，现有小智资源占 2,985,897 字节，剩 3,174,487 字节（约 3.03 MiB）。这部分不能直接当作应用增长空间；要改变分工需重做分区布局并完整刷机。另一个 5 MiB OTA 槽是升级保留空间，不能作为随意存放字库的空闲空间。

运行 RAM 的空闲量和碎片状况尚未测得。已提供只读 MCP `self.study.capacity`，返回内部 RAM / PSRAM 的空闲总量、最大连续块、当前应用分区大小和 SD 内容状态。明天在启动、联网对话、笔顺播放、点读后分别记录，不能用“32 MB 总量”替代这项测试。

```powershell
python tools/capacity_report.py
```

容量脚本已接入 `tools/build.ps1`，读取当前构建选中的实际 CSV、烧录参数及二进制文件，默认应用至少保留 512 KiB，分区溢出直接失败。这是工程安全下限，不代表未来任意功能都能放下。完整离线语音大模型不是当前方案。

## 已准备的资源

- 压缩 UI 字体 28/40 px、完整本内容包的 IPA 大字；已覆盖 `θ`、`ð`、`ŋ`、`ɡ`、长度符号等。不是全汉字字体。
- 六个原创矢量图标及 PNG；沿用现有素材系统，不把概念图当作实际控件。
- 可生成 44 张 SVG/PNG 音标学习卡，文字转为 DejaVu 字体轮廓，避免其他电脑缺字体。这些是预览/后续素材，固件当前用 LVGL 文本直接绘制，不加载整张卡片图片。
- 规、矩共 17 张 300×300 笔顺帧；矩字通过 SD 演示，释义为项目编写示例，不是新华字典原文。
- 字体/笔顺许可证、原始路径数据和可复现生成脚本。音频目录清单有 176 个目标路径，但不包含教学录音。

基础 SD 资源已经随仓库提交，普通准备只需 `python tools/content_pack.py prepare --output dist/my-card`，无需安装 Node.js。下方命令用于重新生成/扩展素材：

```powershell
npm ci --prefix tools/ui-assets
node tools/ui-assets/generate.cjs
node tools/ui-assets/prepare-resources.cjs --output dist/sdcard-ui2
.\tools\preview-ui.ps1 -ContentPath D:\ESP32Projects\ESP32-HanDictionary\dist\sdcard-ui2\handict
```

输出目录须不存在；本机最新内容包为 `dist/sdcard-ui2-final/handict`，约 1 MB。将整个 handict 目录复制到卡根目录。家中路径不同就调整示例 `ContentPath`，脚本自身不绑定公司路径。

自有结构化条目可通过 `--entries local-dictionary.json` 导入，已有使用权的 Hanzi Writer 格式路径可通过 `--strokes-dir local-strokes` 导入。格式校验不代表对内容质量、笔顺标准或版权进行了自动认证；自定义来源需补齐自己的授权与署名。任意新增中文文本仍需重新生成字体或等待后续 SD 字体扩展。
